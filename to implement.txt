Update the POS UI to be fully responsive for smaller desktop screens while keeping everything readable, compact, and usable.

## Goal
Refine the existing POS layout so it works well on smaller desktop resolutions without causing horizontal page scroll or unnecessary full-screen vertical scroll.

## Core Requirements

### 1. Overall Layout
- Make the POS layout compact, responsive, and readable on smaller desktop screens.
- Reduce oversized spacing, padding, gaps, card sizes, and font scaling where needed, but do not make the UI cramped or hard to read.
- The whole page must fit cleanly within the viewport.
- Avoid horizontal scrolling on the entire screen at all costs.
- Avoid vertical scrolling on the main screen/page itself.
- Only the intended internal content areas should scroll.

### 2. Sidebar Behavior
- Fix the `AppSidebar` open/close behavior so it never introduces horizontal overflow.
- When the sidebar expands or collapses, the layout must reflow correctly within the viewport.
- No element should be pushed outside the screen width.
- No temporary width jump or layout shift that causes horizontal scrollbar.
- Ensure the main POS container uses proper width constraints and overflow handling when sidebar state changes.

### 3. Product Panel
- The product panel must be responsive and flexible.
- It should automatically resize based on available space, especially when the sidebar opens/closes and when the cart panel is visible.
- Product cards/list/grid, search bar, category filters, headers, controls, and action buttons must all adapt to smaller widths without overflowing.
- Prevent horizontal scroll in:
  - product list/grid
  - search section
  - category tabs/filters
  - header/toolbars
  - product actions
- Use wrapping, responsive sizing, shrinking, min/max width control, and overflow-safe layout techniques where appropriate.
- The product panel should be the flexible area that adjusts its size.

### 4. Cart Panel
- Keep the cart panel sticky.
- The cart panel must remain stable in size and position.
- Do not let the cart panel resize unpredictably when the screen gets smaller.
- The product panel should adjust first, not the cart panel.
- Keep cart contents usable and readable within the sticky panel.
- Internal cart items area may scroll if needed, but the panel itself should remain fixed/sticky.

### 5. Scrolling Rules
- Remove page-level scrolling for the POS screen if possible.
- The screen itself should stay fixed within the viewport height.
- Only internal sections should scroll:
  - product items display
  - cart items list
- Header, filters, summary, and important controls should remain visible and stable.
- Do not allow the full browser page to scroll because of layout overflow.

### 6. Responsiveness and Readability
- Optimize for smaller desktop/laptop screens.
- Keep text readable.
- Keep buttons tappable/clickable.
- Maintain clean spacing hierarchy.
- Avoid oversized UI elements that waste space.
- Avoid compressed layouts that hurt usability.

## Technical Expectations
- Audit the current layout for any cause of `overflow-x`.
- Ensure parent containers use proper `min-w-0`, `overflow-hidden`, `flex`, and responsive width rules where needed.
- Prevent children inside flex/grid layouts from forcing the layout wider than the viewport.
- Make sticky sections work correctly within the viewport height.
- Use internal scroll regions instead of whole-page scroll.
- Preserve current business logic and functionality; this task is UI/layout refinement only.

## Expected Result
The POS screen should:
- fit cleanly on smaller desktop screens
- have no horizontal screen scrolling
- have no unnecessary page-level vertical scrolling
- keep the cart panel sticky and stable
- allow only the items sections to scroll
- remain readable, clean, and efficient
- behave correctly when the sidebar is opened or closed
